One unit is a small piece of work: one behaviour, three to five failing tests, at most three code files. A clock runs every five minutes and moves each unit one step. Tap a step.

Way back: the first refusal of build check, review or landing sends the unit back to Build with the finding. The second refusal stops it for a split. A stop card goes to the chief of staff, never to the human.

Cut

The chief of staff sizes the unit: one behaviour in a short paragraph with a named sabotage, three to five failing tests, at most three code files, a named seam and an estimate of at most two hours. Code refuses anything larger. Before the cut, Sweeper Sid checks the row is not already done and the plan coverage auditor checks nothing is dropped. The unit is queued from the live checkout. Without a brief, Quill writes one and code checks it.

Red check

Each named test must fail because the unit's code is missing, not because the test file is broken. Every other test must pass, except the tests of other units still in the queue, or stopped with an open card. A brief that cites a missing file or a runtime file is refused.

Build

The builder role runs with the exact model the install probe pinned. It gets the brief and the unit, may touch only the listed files, and may not change tests. Its time box is twice the estimate. The program commits the work. A rebuild starts again from the cut, with the finding; model time over twice the estimate sends the unit to a split.

Build check

Only listed files changed, test files are unchanged, the named tests pass, every new check is protected by a named test (the guard removes each one), and the whole suite passes.

Review

Inspector Grumble, the reviewer role, runs on a different model when one answered the probe, else in a fresh session with a different review prompt (shown as weaker). It runs the tests, the suite and the named sabotage, and writes a JSON form. Lockjaw joins on risky files and Thomasina on user-facing surfaces. Code decides the verdict: only a complete finding of a listed kind, inside the unit's files, blocks; every note becomes a backlog row.

Landing

The unit's own commits are replayed onto the newest main. The change must equal the reviewed change. The whole suite runs on the merged result. The pull request is opened. In direct mode the factory merges it by its exact head commit; in auto mode GitHub merges it once the branch rules are met; in pr-only mode people merge it. The clock watches an open pull request until it is merged. Landings go one at a time.

The crew and stops

Every crew agent starts only on its trigger in the crew file, with the model of the role it uses; its answer is a form that code accepts or refuses, and it earns cookies or slaps on the Factory metrics tab. One unit is stopped with hold, which ends its process at once, and returns only through release after its re-cut validates. A row is marked done by code after the conformance and claim checks.

When the machinery fails

A model error, a denied tool, a failed fetch or a failed GitHub call is never the unit's fault and uses no attempt. A usage limit pauses every build and review until it resets; the daily budget does the same and asks the human. Retries are capped, then the unit stops with a card.
